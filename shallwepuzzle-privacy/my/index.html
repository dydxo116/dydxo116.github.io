2. ဂိမ်းမှတ်တမ်းနှင့် သင့်စက်ထဲရှိ အချက်အလက်

ပထမဆုံး အသုံးပြုချိန်တွင် ကာကွယ်ပေးရမည့် အသုံးပြုသူ သို့မဟုတ် အရွယ်ရောက်သူ ဖြစ်မဖြစ် ဆုံးဖြတ်ရန် မွေးသက္ကရာဇ်ကို စက်၏ memory အတွင်း၌သာ စစ်ဆေးပါသည်။ မွေးသက္ကရာဇ်နှင့် အသက်ကို သိမ်းဆည်းခြင်း သို့မဟုတ် ဆာဗာသို့ ပို့ခြင်း မပြုပါ။ ယေဘုယျ အသုံးပြုသူ အုပ်စုနှင့် ရွေးချယ်နိုင်သော ခွဲခြမ်းစိတ်ဖြာခြင်း/ပျက်ကျမှု အစီရင်ခံခြင်း ရွေးချယ်မှုကိုသာ Android backup မှ ဖယ်ထားသော စက်တွင်း storage တွင် သိမ်းပါသည်။ မွေးသက္ကရာဇ်ကို ကျော်သွားလျှင် သို့မဟုတ် ဆက်တင်များ မရှိ/ပျက်စီးနေလျှင် ကာကွယ်ပေးရမည့် အသုံးပြုသူအဖြစ် သတ်မှတ်ပါသည်။

အဆင့် တိုးတက်မှု၊ ကြယ်၊ အမြင့်ဆုံးရမှတ်၊ မပြီးသေးသော ဂိမ်း၊ မကြာသေးမီက ကစားခဲ့သော ဂိမ်း၊ အသံ၊ တုန်ခါမှုနှင့် ဘာသာစကား ဆက်တင်၊ လမ်းညွှန်ချက် အခြေအနေ၊ ကြော်ငြာပြသသည့် အကြားကာလနှင့် သဘောတူညီချက် ရွေးချယ်မှုများကို အက်ပ် သို့မဟုတ် SDK ၏ စက်တွင်း storage တွင် သိမ်းဆည်းပါသည်။ ဂိမ်းမှတ်တမ်းဖိုင်များကို upload လုပ်ပြီး ထပ်တူပြုသည့် ဂိမ်းအကောင့် သို့မဟုတ် ကိုယ်ပိုင်ဆာဗာ မရှိပါ။

Google Play Games backup သည် ရွေးချယ်နိုင်သော လုပ်ဆောင်ချက်ဖြစ်ပြီး ကြော်ငြာဆိုင်ရာ အသက်ကာကွယ်မှုနှင့် သီးခြားဖြစ်ပါသည်။ ချိတ်ဆက်မှု အသိပေးချက်ကို ဖတ်ပြီး ချိတ်ဆက်ရန် ရွေးချယ်မှသာ SDK ကို စတင်ပါသည်။ Google sign-in နှင့် storage ခွင့်ပြုချက်ကို ပေးထားလျှင် အဆင့်၊ ကြယ်နှင့် အကောင်းဆုံးမှတ်တမ်းများကို Google Saved Games တွင် သိမ်းပြီး စက်များအကြား ပေါင်းစည်းပါသည်။ မွေးသက္ကရာဇ်၊ ကြော်ငြာ ရွေးချယ်မှု၊ ဆက်တင်များနှင့် မပြီးသေးသော ဘုတ်များကို ဤ backup တွင် မထည့်ပါ။ Google သည် ဝန်ဆောင်မှု ပေးရန်နှင့် တိုးတက်စေရန် Play Games ပရိုဖိုင်နှင့် SDK ၏ ကိုယ်ပိုင် အသုံးပြုမှု/diagnostic ဒေတာကိုလည်း ကိုင်တွယ်ပါသည်။ ဤအက်ပ်သည် သူငယ်ချင်းစာရင်း၊ အီးမေးလ် သို့မဟုတ် လူမှုရေး လုပ်ဆောင်ချက်များကို မတောင်းဆိုသလို Play Games ဒေတာကို ကြော်ငြာအတွက်လည်း အသုံးမပြုပါ။ ကြီးကြပ်ခံ ကလေးအကောင့်များတွင် Google ၏ မိဘခွင့်ပြုချက်နှင့် ဝန်ဆောင်မှု ပံ့ပိုးမှုပေါ် မူတည်သောကြောင့် အကောင့်တိုင်းတွင် သိမ်းဆည်းနိုင်မည်ဟု အာမမခံပါ။ မချိတ်ဆက်လျှင် သို့မဟုတ် ခွင့်ပြုချက် ငြင်းပယ်လျှင်လည်း ဂိမ်းအားလုံးကို စက်တွင်း မှတ်တမ်းဖြင့် ဆက်ကစားနိုင်ပြီး ကာကွယ်ထားသော ကြော်ငြာနှင့် Firebase ဆက်တင်များ ဆက်လက် အကျုံးဝင်ပါသည်။ backup ရွေးချယ်မှုကို Android backup မှ ဖယ်ထားသော စက်တွင်း storage တွင် သိမ်းပါသည်။ လက်ရှိ အသုံးပြုသူများလည်း အသိပေးချက်ကို တစ်ကြိမ် မြင်ရမည်ဖြစ်ပြီး နောင်တွင် အက်ပ်ဆက်တင်မှ ချိတ်ဆက်နိုင်ပါသည်။

အက်ပ်သည် စာရင်းသွင်းခြင်း သို့မဟုတ် sign-in မလိုအပ်ပါ။ သင့်အမည်၊ ဖုန်းနံပါတ်၊ လိပ်စာ၊ အဆက်အသွယ်စာရင်း၊ ဓာတ်ပုံ၊ မိုက်ခရိုဖုန်း အသံသွင်းချက် သို့မဟုတ် တိကျသော GPS တည်နေရာကို ထည့်ရန် မတောင်းဆိုသလို ထိုအချက်အလက်များကို စုဆောင်းသည့် လုပ်ဆောင်ချက်လည်း မပါဝင်ပါ။ ကျွန်ုပ်တို့ထံ အီးမေးလ် ပို့လျှင် သင့်အီးမေးလ်လိပ်စာနှင့် စာကို ကျွန်ုပ်တို့ လက်ခံရရှိပါသည်။

Android backup နှင့် restore ကို ဖွင့်ထားလျှင် သင့်စက်နှင့် Google အကောင့် ဆက်တင်ပေါ် မူတည်၍ အက်ပ်ဒေတာ အချို့ကို operating system ပံ့ပိုးသူက backup လုပ်ပြီး ပြန်ထည့်သွင်းပြီးနောက် ပြန်ရယူနိုင်ပါသည်။ ၎င်းသည် ဖန်တီးသူ လည်ပတ်သော ဂိမ်းအကောင့် မဟုတ်ဘဲ Android backup ဆက်တင်တွင် စီမံနိုင်ပါသည်။

3. အလိုအလျောက် ကိုင်တွယ်သော အချက်အလက်နှင့် ရည်ရွယ်ချက်

ထုတ်ဝေထားသော အက်ပ်တွင် အောက်ပါ Google SDK များ ပါဝင်ပါသည်။ ၎င်းတို့သည် သင်အက်ပ်ကို သုံးသည့်အခါ သို့မဟုတ် ကွန်ရက်နှင့် ချိတ်ဆက်သည့်အခါ အချက်အလက်ကို အလိုအလျောက် ကိုင်တွယ်နိုင်ပါသည်။ အတိအကျ အတိုင်းအတာသည် SDK ဗားရှင်း၊ စက်နှင့် ဒေသ ဆက်တင်၊ သဘောတူညီချက် အခြေအနေနှင့် Google ဝန်ဆောင်မှု ဆက်တင်ပေါ် မူတည်ပါသည်။

update စစ်ဆေးရာတွင် အသက်အရွယ်မရွေး သီးခြား Firebase Remote Config နှင့် Firebase Installations ဝန်ဆောင်မှုများကို အသုံးပြုနိုင်ပါသည်။ ဆက်တင်ပေးပို့ရန်နှင့် ဤလုပ်ဆောင်ချက် အလုပ်လုပ်ရန် update အတွက်သာ သုံးသော installation identifier နှင့် authentication token၊ အက်ပ်ဗားရှင်း၊ ဘာသာစကား၊ operating system နှင့် ချိတ်ဆက်ရာတွင် သုံးသော IP လိပ်စာကို ကိုင်တွယ်ပါသည်။ ၎င်းသည် ရွေးချယ်နိုင်သော ခွဲခြမ်းစိတ်ဖြာခြင်းနှင့် ပျက်ကျမှု အစီရင်ခံခြင်းနှင့် သီးခြားဖြစ်ပြီး update စစ်ဆေးခြင်းကြောင့် Analytics၊ Crashlytics သို့မဟုတ် ကြော်ငြာ ID စုဆောင်းခြင်း စတင်မည် မဟုတ်ပါ။ ဤစစ်ဆေးမှုများအတွက် ကြော်ငြာ သို့မဟုတ် ခွဲခြမ်းစိတ်ဖြာမှုဆိုင်ရာ user property၊ စမ်းသပ်မှု သို့မဟုတ် personalization ကို အသုံးမပြုပါ။

ဝန်ဆောင်မှုကိုင်တွယ်နိုင်သော အချက်အလက်ရည်ရွယ်ချက်
Google AdMob / Google Mobile AdsIP လိပ်စာနှင့် ၎င်းမှ ခန့်မှန်းသော အကြမ်းဖျင်း တည်နေရာ၊ Android ကြော်ငြာ ID၊ app set ID နှင့် အခြား စက်/အကောင့်ဆိုင်ရာ identifier များ၊ အက်ပ်ဖွင့်ခြင်း၊ ကြော်ငြာပြသခြင်း၊ နှိပ်ခြင်းနှင့် ဗီဒီယိုကြည့်ခြင်းကဲ့သို့ အပြန်အလှန် လုပ်ဆောင်မှုများ၊ အက်ပ်နှင့် ကြော်ငြာ SDK ၏ စွမ်းဆောင်ရည်နှင့် diagnostic အချက်အလက်။ (ကာကွယ်ထားသော ကြော်ငြာ တောင်းဆိုမှုများတွင် ကလေးအတွက် သတ်မှတ်ချက်ကို အသုံးပြုပြီး Android ကြော်ငြာ ID ပို့ခြင်းကို တားဆီးပါသည်။)ကိုယ်ပိုင်ပြင်ဆင်မထားသော ကြော်ငြာ ပြသခြင်းနှင့် တိုင်းတာခြင်း၊ လုံခြုံရေးနှင့် လိမ်လည်မှု ကာကွယ်ခြင်း
Google User Messaging Platform (UMP)ဒေသနှင့် စက်အချက်အလက်၊ သဘောတူညီချက် အခြေအနေနှင့် ကြော်ငြာ ကိုယ်ရေးအချက်အလက် ရွေးချယ်မှုများ၊ ထိုရွေးချယ်မှုများကို အသုံးချရန် လိုအပ်သော identifier/ဆက်တင် အချက်အလက်လိုအပ်သော ကြော်ငြာ သဘောတူညီချက် စာများ ပြသခြင်း၊ ရွေးချယ်မှုများ သိမ်းဆည်းခြင်းနှင့် ကြော်ငြာ တောင်းဆိုမှုများတွင် အသုံးချခြင်း
Google Analytics for Firebaseသဘောတူထားသော အရွယ်ရောက်သူများအတွက်သာ: app instance/installation identifier၊ စက်မော်ဒယ်၊ operating system၊ အက်ပ်ဗားရှင်းနှင့် ဘာသာစကား၊ session/မျက်နှာပြင် event များနှင့် SDK က ကိုင်တွယ်သော IP/အကြမ်းဖျင်း ဒေသ အချက်အလက်။ Analytics ၏ ကြော်ငြာ ID စုဆောင်းခြင်း၊ ကြော်ငြာ storage၊ ကြော်ငြာ user data နှင့် ကြော်ငြာ personalization signal များကို ပိတ်ထားပါသည်။ ဂိမ်းနှင့် အဆင့် လုပ်ဆောင်မှု၊ ကစားရလဒ်နှင့် ပြန်ကြိုးစားမှု၊ ကြော်ငြာပြသမှုနှင့် ဆက်တင် ပြောင်းလဲမှုများကိုလည်း ခွဲခြမ်းစိတ်ဖြာပါသည်။အသုံးပြုပုံ၊ လုပ်ဆောင်ချက် အသုံးပြုမှုနှင့် တည်ငြိမ်မှု လမ်းကြောင်းများကို နားလည်ပြီး ဝန်ဆောင်မှုကို တိုးတက်စေခြင်း
Firebase Crashlytics နှင့် Firebase installation ဝန်ဆောင်မှုများသဘောတူထားသော အရွယ်ရောက်သူများအတွက်သာ: installation/session identifier၊ ပျက်ကျမှု/အမှား ဖြစ်ချိန်နှင့် stack trace၊ အမှား စာ၊ အက်ပ်ဗားရှင်း၊ operating system၊ စက်မော်ဒယ်၊ memory နှင့် ဆက်စပ် diagnostic အချက်အလက်၊ ပျက်ကျမှုမတိုင်မီ ဆက်စပ် အက်ပ် event များအမှားများကို ရှာဖွေ စုံစမ်းခြင်း၊ ထိခိုက်ခံရသော installation များကို တိုင်းတာခြင်းနှင့် ယုံကြည်စိတ်ချရမှု တိုးတက်စေခြင်း
Firebase Remote Config / Firebase Installationsupdate အတွက်သာ သုံးသော installation identifier နှင့် authentication token၊ အက်ပ်ဗားရှင်း၊ ဘာသာစကား၊ operating system နှင့် ချိတ်ဆက်မှု အချက်အလက်အကြံပြုထားသော နှင့် မဖြစ်မနေ လိုအပ်သော အက်ပ်ဗားရှင်း ဆက်တင်များ ပေးပို့ခြင်း၊ cache လုပ်ခြင်းနှင့် update လုပ်ဆောင်ချက် ပေးခြင်း
Google Play In-App Updatesအက်ပ်နှင့် စက် metadata၊ ထည့်သွင်းထားသော အက်ပ်ဗားရှင်း၊ update အခြေအနေနှင့် အမှား အချက်အလက်Google Play မှတစ်ဆင့် update ရနိုင်မှု စစ်ဆေးခြင်း၊ ဒေါင်းလုဒ်လုပ်ခြင်း၊ ထည့်သွင်းခြင်းနှင့် အက်ပ်ကို ပြန်စခြင်း

သင့်အမည်၊ အီးမေးလ်လိပ်စာ သို့မဟုတ် ဖုန်းနံပါတ်ကို Analytics user ID အဖြစ် မသတ်မှတ်ပါ။ ဂိမ်းမှတ်တမ်းဖိုင်များကိုလည်း analytics event အဖြစ် မပို့ပါ။ စက်နှင့် အက်ပ် identifier များသည် သင့်အမည်ရင်း မဟုတ်သော်လည်း သက်ဆိုင်ရာ ဥပဒေအရ ကိုယ်ရေးအချက်အလက် ဖြစ်နိုင်ပါသည်။

အသက် ဆုံးဖြတ်ခြင်း မပြုမီ၊ သို့မဟုတ် အသက် 18 နှစ်အောက် (သို့) အသက်မသိရသော ကာကွယ်ခံ အသုံးပြုသူများအတွက် အက်ပ်သည် Firebase Core၊ Analytics သို့မဟုတ် Crashlytics ကို မစတင်ပါ။ အရွယ်ရောက်သူများသည် အသုံးပြုမှု ခွဲခြမ်းစိတ်ဖြာခြင်းနှင့် ပျက်ကျမှု အစီရင်ခံခြင်းကို ကိုယ်တိုင် ရွေးချယ် ဖွင့်နိုင်ပြီး ဆက်တင်တွင် နှစ်ခုလုံးကို တပြိုင်နက် ပိတ်နိုင်ပါသည်။

4. Google နှင့် အခြား ဝန်ဆောင်မှုပေးသူများ

အထက်ဖော်ပြပါ အချက်အလက်များကို ကြော်ငြာ၊ ခွဲခြမ်းစိတ်ဖြာခြင်းနှင့် ပျက်ကျမှု အစီရင်ခံခြင်းအတွက် Google LLC နှင့် သက်ဆိုင်ရာ ဝန်ဆောင်မှု စည်းမျဉ်းတွင် ဖော်ပြထားသော Google ၏ ဆက်စပ်ကုမ္ပဏီများထံ ပို့ပြီး ကိုင်တွယ်နိုင်ပါသည်။ ဝန်ဆောင်မှုနှင့် ၎င်း၏ စည်းမျဉ်းပေါ် မူတည်၍ Google သည် ကျွန်ုပ်တို့၏ processor အဖြစ် သို့မဟုတ် သီးခြား controller အဖြစ် ဆောင်ရွက်နိုင်ပါသည်။

သင့်ဒေသ၊ ရွေးချယ်မှုများနှင့် ကြော်ငြာ ဆက်တင်ပေါ် မူတည်၍ Google ၏ ကြော်ငြာနည်းပညာ ပံ့ပိုးသူများက ကြော်ငြာ တောင်းဆိုမှုနှင့် တိုင်းတာမှု အချက်အလက်ကို ကိုင်တွယ်နိုင်ပါသည်။ သဘောတူညီချက် စာ ပြသထားလျှင် သက်ဆိုင်ရာ ပံ့ပိုးသူများနှင့် ရွေးချယ်မှုများအတွက် ထိုစာနှင့် Google ၏ ဆက်စပ် အချက်အလက်ကို ကြည့်ပါ။

အကူအညီ အီးမေးလ်များကို Gmail (Google) ဖြင့် လက်ခံ သိမ်းဆည်းပါသည်။ အီးမေးလ် ပံ့ပိုးသူသည် သင့်အီးမေးလ်လိပ်စာ၊ စာနှင့် သင်ပို့ရန် ရွေးချယ်သော ပူးတွဲဖိုင်များကို ကိုင်တွယ်နိုင်ပါသည်။ မေးမြန်းချက် ဖြေရှင်းရန် လိုအပ်သော အချက်အလက်ကိုသာ ပို့ပါ။

ကိုယ်ရေးအချက်အလက်ကို သီးခြား ရောင်းချခြင်း မပြုပါ။ ကြော်ငြာအတွက် ထုတ်ဖော်ခြင်းကို အချို့ ဥပဒေများအရ 'မျှဝေခြင်း' သို့မဟုတ် ပစ်မှတ်ထား ကြော်ငြာအတွက် ကိုင်တွယ်ခြင်းဟု သတ်မှတ်နိုင်ပါသည်။ အောက်ပါ ရွေးချယ်မှုများကို ကြည့်ပါ။ ဥပဒေဆိုင်ရာ တာဝန် သို့မဟုတ် တရားဝင် တောင်းဆိုမှုကို လိုက်နာရန် သို့မဟုတ် သင် တောင်းဆိုထားသည်ကို ဆောင်ရွက်ရန် လိုအပ်လျှင် အကန့်အသတ်ရှိသော အချက်အလက်ကိုလည်း ထုတ်ဖော်နိုင်ပါသည်။

5. ကြော်ငြာ ရွေးချယ်မှု၊ သဘောတူညီချက်နှင့် ကိုင်တွယ်ရန် အခြေခံ

ကြော်ငြာ ကိုယ်ရေးအချက်အလက် တောင်းဆိုမှုနှင့် ကြော်ငြာ တောင်းဆိုမှု မပြုမီ အက်ပ်သည် စက်တွင်း အသက်ဆုံးဖြတ်ချက် သို့မဟုတ် ကျော်ရန် ရွေးချယ်မှုကို စောင့်ပါသည်။ အရွယ်ရောက်သူများအတွက် ရွေးချယ်နိုင်သော ခွဲခြမ်းစိတ်ဖြာခြင်း/ပျက်ကျမှု အစီရင်ခံခြင်း သဘောတူညီချက်ကို မူလအားဖြင့် ရွေးထားခြင်း မရှိဘဲ ငြင်းပယ်လျှင်လည်း မည်သည့်ဂိမ်းကိုမျှ ကန့်သတ်မည် မဟုတ်ပါ။ ဆက်တင်တွင် 'အသုံးပြုမှု ခွဲခြမ်းစိတ်ဖြာခြင်းနှင့် ပျက်ကျမှု အစီရင်ခံခြင်း' ကို ပိတ်လျှင် နောက်ထပ် စုဆောင်းခြင်းကို ရပ်ပြီး စက်ထဲရှိ မပို့ရသေးသော ပျက်ကျမှု အစီရင်ခံစာများကို ဖျက်ပါသည်။ ပို့ပြီးသား မှတ်တမ်းများကိုမူ အလိုအလျောက် မဖျက်ပါ။

Google UMP က ကြော်ငြာ တောင်းဆိုနိုင်ကြောင်း ပြသပြီးမှသာ ကြော်ငြာ SDK က ကြော်ငြာ တောင်းဆိုပါသည်။ သင့်ဒေသနှင့် Google ၏ လိုအပ်ချက်ပေါ် မူတည်၍ ကြော်ငြာ အသိပေးချက် သို့မဟုတ် သဘောတူညီချက် စာ ပေါ်လာနိုင်ပါသည်။ ကိုယ်ရေးအချက်အလက် ရွေးချယ်မှုများ လိုအပ်သည့်အခါ အက်ပ်ဆက်တင်ရှိ ကြော်ငြာ ကိုယ်ရေးအချက်အလက် ရွေးချယ်မှု အပိုင်းတွင် ပြန်ကြည့်ခြင်း သို့မဟုတ် ပြောင်းခြင်း ပြုလုပ်နိုင်ပါသည်။ ဤအပိုင်းကို UMP က လိုအပ်သည်ဟု ဆုံးဖြတ်မှသာ ပြသပါသည်။

အက်ပ်သည် G အဆင့် သတ်မှတ်ထားသော ကိုယ်ပိုင်ပြင်ဆင်မထားသည့် ကြော်ငြာများကို တောင်းဆိုပါသည်။ အသက် 18 နှစ်အောက် သို့မဟုတ် အသက်မသိရသော ကာကွယ်ခံ အသုံးပြုသူများအတွက် Google ၏ ကလေးအတွက် သတ်မှတ်ချက်နှင့် UMP ၏ သဘောတူညီချက်ပေးနိုင်သည့် အသက်အောက် ဆက်တင်ကို အသုံးပြုပါသည်။ ကိုယ်ပိုင်ပြင်ဆင်မထားသော သို့မဟုတ် ကန့်သတ်ထားသော ကြော်ငြာများသည်လည်း IP/အကြမ်းဖျင်း တည်နေရာ၊ ခွင့်ပြုထားသော identifier များ၊ အပြန်အလှန် လုပ်ဆောင်မှုနှင့် diagnostic များကို ကိုင်တွယ်နိုင်ပါသည်။ ကြော်ငြာ သဘောတူညီချက်ကို ငြင်းပယ်ခြင်း သို့မဟုတ် ကြော်ငြာ မတင်နိုင်ခြင်းကြောင့် ကစားခြင်းကို မတားဆီးပါ။

ID ဖျက်ခြင်းကဲ့သို့ ရနိုင်သော ကြော်ငြာ ID ရွေးချယ်မှုများကို Android ၏ ကိုယ်ရေးအချက်အလက်/ကြော်ငြာ ဆက်တင်တွင် စီမံနိုင်ပါသည်။ အမည်နှင့် ရွေးချယ်စရာများသည် စက်အလိုက် ကွဲပြားပါသည်။ Google အကောင့်၏ ကြော်ငြာ ထိန်းချုပ်မှုများသည် Google ဝန်ဆောင်မှုများ အတိုင်းအတာအတွင်း သီးခြား သက်ရောက်ပါသည်။

သက်ဆိုင်ရာ ဥပဒေပေါ် မူတည်၍ ဝန်ဆောင်မှု ပေးခြင်း၊ ဝန်ဆောင်မှု ယုံကြည်စိတ်ချရမှု၊ လုံခြုံရေးနှင့် တိုးတက်မှုဆိုင်ရာ တရားဝင် အကျိုးစီးပွား၊ ဥပဒေဆိုင်ရာ တာဝန် သို့မဟုတ် လိုအပ်လျှင် သဘောတူညီချက်ကို အခြေခံ၍ ကိုင်တွယ်ပါသည်။ သဘောတူညီချက်ကို အခြေခံသည့် ကိုင်တွယ်မှုအတွက် သဘောတူညီချက်ကို ရုပ်သိမ်းနိုင်ပြီး ရုပ်သိမ်းခြင်းသည် ယခင် ကိုင်တွယ်မှု၏ တရားဝင်မှုကို မထိခိုက်ပါ။ သဘောတူညီချက် လိုအပ်သော ဒေသများတွင် သက်ဆိုင်ရာ လိုအပ်ချက်များကို ဖြည့်ဆည်းရပါမည်။ ကြော်ငြာ သဘောတူညီချက်နှင့် ခွဲခြမ်းစိတ်ဖြာခြင်း/diagnostic ကိုင်တွယ်မှုတို့၏ အတိုင်းအတာ သီးခြားဖြစ်ပါသည်။

6. သိမ်းဆည်းထားမှုနှင့် ဖျက်ခြင်း

အချက်အလက်သိမ်းဆည်းထားမှုနှင့် ဖျက်ခြင်း
စက်တွင်း ဂိမ်းမှတ်တမ်းနှင့် ဆက်တင်သင့်စက်ထဲတွင် ရှိနေသရွေ့ သိမ်းထားပါသည်။ အက်ပ်၏ ကစားမှတ်တမ်း ပြန်စခြင်းသည် ထိုလုပ်ဆောင်ချက် အကျုံးဝင်သော ပြီးဆုံးထားသည့် အဆင့်၊ ကြယ်နှင့် အခြား တိုးတက်မှု မှတ်တမ်းများကို ရှင်းလင်းသော်လည်း ဆက်တင်၊ အချို့ အမြင့်ဆုံးရမှတ် မှတ်တမ်းနှင့် SDK ဒေတာ ကျန်နိုင်ပါသည်။ စက်တွင်း ဒေတာကို ဖယ်ရှားရန် Android ဆက်တင်တွင် အက်ပ်၏ storage ကို ရှင်းပါ။ uninstall လုပ်ခြင်း၊ backup သိမ်းဆည်းထားမှုနှင့် ပြန်ရယူခြင်းတို့သည် စက်နှင့် backup ဆက်တင်ပေါ် မူတည်ပါသည်။
Analytics ဒေတာAnalytics property ၏ သိမ်းဆည်းမှု ဆက်တင်နှင့် ဖျက်ခြင်း လုပ်ထုံးလုပ်နည်းအတိုင်း ကိုင်တွယ်ပါသည်။ စံ GA4 သည် ယေဘုယျအားဖြင့် user/event အဆင့် ဆက်တင်အတွက် 2 လ သို့မဟုတ် 14 လ ပေးပါသည်။ လုပ်ဆောင်မှုအပေါ် အခြေခံ သက်တမ်းတိုးခြင်းနှင့် အခြား ဆက်တင်များက သိမ်းဆည်းချိန်ကို ထိခိုက်နိုင်ပါသည်။ ဤကန့်သတ်ချက်များသည် စံ စုစည်း အစီရင်ခံစာ အားလုံးတွင် တစ်ပုံစံတည်း မသက်ရောက်ဘဲ စုစည်း စာရင်းအင်းများသည် ပိုကြာစွာ ကျန်နိုင်ပါသည်။
Crashlytics ဒေတာGoogle ၏ ဖော်ပြချက်အရ ပျက်ကျမှု stack trace နှင့် ဆက်စပ် identifier များကို 90 ရက် သိမ်းထားပြီးနောက် live နှင့် backup စနစ်များမှ ဖယ်ရှားခြင်း လုပ်ငန်းစဉ် စတင်ပါသည်။ ၎င်းသည် 90 ရက်မြောက်နေ့တွင် ဖျက်ပြီးစီးသည်ဟု မဆိုလိုပါ။
ကြော်ငြာနှင့် သဘောတူညီချက် ဒေတာကြော်ငြာ ပြသခြင်း၊ တိုင်းတာခြင်း၊ လိမ်လည်မှု ကာကွယ်ခြင်းနှင့် ရွေးချယ်မှုများကို လိုက်နာခြင်းအတွက် လိုအပ်သော ကာလအတွင်း Google နှင့် သက်ဆိုင်ရာ ပံ့ပိုးသူများ၏ သိမ်းဆည်း/ဖျက်ခြင်း မူဝါဒအတိုင်း ကိုင်တွယ်ပါသည်။ စက်တွင်း သဘောတူညီချက် ဆက်တင်နှင့် ပံ့ပိုးသူများ၏ မှတ်တမ်းများ၏ သိမ်းဆည်းကာလ ကွဲပြားနိုင်ပါသည်။
အကူအညီ အီးမေးလ်မေးမြန်းချက်နှင့် လိုအပ်သော နောက်ဆက်တွဲ ဆောင်ရွက်မှု ပြီးဆုံးသည်အထိ သိမ်းထားပြီး ထို့နောက် ဖျက်ပါသည်။ ဥပဒေအရ သိမ်းထားရန် လိုအပ်လျှင် လိုအပ်သော အချက်အလက်ကိုသာ သက်ဆိုင်ရာ ဥပဒေကာလအတွက် သိမ်းထားပါသည်။
Google Play Games backup နှင့် ဝန်ဆောင်မှု ဒေတာမှတ်တမ်းများကို သင့် Google အကောင့်ရှိ Saved Games တွင် သိမ်းထားပြီး Google ၏ သိမ်းဆည်း/ဖျက်ခြင်း လုပ်ထုံးလုပ်နည်းအတိုင်း ဖြစ်ပါသည်။ sign-in အကောင့်ကို Android ၏ Google ဆက်တင်တွင် စီမံပြီး ဤဂိမ်း၏ ဒေတာကို သင့် Play Games ပရိုဖိုင် သို့မဟုတ် Google အကောင့်၏ ဂိမ်းဒေတာ ထိန်းချုပ်မှုမှ ဖျက်နိုင်ပါသည်။ uninstall လုပ်ခြင်း သို့မဟုတ် စက်တွင်း ကစားမှတ်တမ်း ပြန်စခြင်းဖြင့် cloud ရှိ မိတ္တူကို မဖျက်ပါ။ ချိတ်ဆက်ထားစဉ် မှတ်တမ်းများ ပြန်ပေါင်းစည်းနိုင်ပါသည်။

11. ဤမူဝါဒ ဝဘ်ဆိုက်

ဤစာမျက်နှာတွင် ဖန်တီးသူ ထည့်သွင်းထားသော ကြော်ငြာ၊ ဝင်ရောက်သူ ခွဲခြမ်းစိတ်ဖြာမှု SDK၊ ခြေရာခံ script သို့မဟုတ် ခြေရာခံ cookie မရှိပါ။ GitHub Pages တွင် တင်ထားပါသည်။ GitHub သည် ၎င်း၏ ကိုယ်ရေးအချက်အလက် ထုတ်ပြန်ချက်အရ လုံခြုံရေးနှင့် ဆက်စပ် ရည်ရွယ်ချက်များအတွက် ဝင်ရောက်သူ၏ IP လိပ်စာနှင့် အခြား ချိတ်ဆက်မှု အချက်အလက်ကို ကိုင်တွယ်နိုင်ပါသည်။ ပြင်ပ မူဝါဒ link ကို နှိပ်လျှင် ထိုပံ့ပိုးသူ၏ ဝဘ်ဆိုက်နှင့် မူဝါဒသို့ ရောက်ပါမည်။

အက်ပ်သည် အဆင့် content update များအတွက် GitHub Pages ကို စစ်ဆေးပြီး ပြောင်းလဲထားသော ဂိမ်းဒေတာကို ဒေါင်းလုဒ်လုပ်ပါသည်။ ဤတောင်းဆိုမှုများတွင် Play Games အကောင့် အချက်အလက် သို့မဟုတ် ကိုယ်ပိုင် ကစားမှတ်တမ်း မပါဝင်ပါ။ GitHub သည် ၎င်း၏ ကိုယ်ရေးအချက်အလက် ထုတ်ပြန်ချက်အရ content ပေးပို့ရန်နှင့် လုံခြုံစေရန် IP လိပ်စာနှင့် အခြား ပုံမှန် ချိတ်ဆက်မှု အချက်အလက်ကို ကိုင်တွယ်နိုင်ပါသည်။

12. ပြောင်းလဲမှုများနှင့် ဆက်စပ် မူဝါဒများ

အက်ပ် လုပ်ဆောင်ချက်များ၊ ဝန်ဆောင်မှုပေးသူများ သို့မဟုတ် ဥပဒေများ ပြောင်းလဲသည့်အခါ ဤမူဝါဒကို ပြင်ဆင်ပြီး အသက်ဝင်သည့်နေ့ကို ပြောင်းနိုင်ပါသည်။ အရေးကြီးသော ပြောင်းလဲမှုများအတွက် ထပ်ဆောင်း အသိပေးချက် သို့မဟုတ် သဘောတူညီချက် လိုအပ်လျှင် ထိုလိုအပ်ချက်များကို လိုက်နာပါမည်။ Google နှင့် GitHub ၏ လုပ်ဆောင်ပုံနှင့် ရနိုင်သော ထိန်းချုပ်မှုများအတွက် အောက်ပါ တရားဝင် အရင်းအမြစ်များကို ကြည့်ပါ။

  • Google Mobile Ads SDK ဒေတာ ထုတ်ဖော်ခြင်း။
  • Google ကြော်ငြာကိုယ်ရေးကိုယ်တာအချက်အလက်
  • Google ကြော်ငြာထိန်းချုပ်မှုများ
  • Google Analytics ဒေတာကို ထိန်းသိမ်းခြင်း။
  • Firebase ကိုယ်ရေးကိုယ်တာနှင့် Crashlytics ထိန်းသိမ်းမှု
  • Firebase ဒေတာလုပ်ဆောင်ခြင်းဆိုင်ရာ စည်းမျဉ်းများ
